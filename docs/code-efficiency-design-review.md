# KineVault efficiency and design review

Reviewed 2–3 October 2026. Scope: current working tree, including uncommitted workshop changes. No application code changed.

The biggest opportunities are reducing workshop work per frame, reducing repeated database requests, and simplifying the visible controls. Preserve the existing neutral visual identity.

This is a broad source and UI review, not proof that every possible defect has been found. Production bundle size, browser frame times, concurrency, and fresh database query plans were not benchmarked. Items marked **profile first** are candidates, not measured bottlenecks.

- Inspected app routes/components, data loaders, motion/rig code, representative effective SQL/search/worker definitions, asset metadata, dependencies, Docker and CI. Historical migrations and every database policy were not exhaustively audited.
- No production build was run while the shared development server was active. No full mutation-heavy E2E/media suite or database benchmark was rerun. Both themes were exercised by the appearance test; the full visual matrix remains to be checked after changes.

Keep existing strengths: server-side filtering and pagination, normalized taxonomies, atomic save commands, idempotent draft IDs, private recovery, demand-mode canvases, explicit GPU cleanup, reduced-motion behavior in the public gallery, and lazy public detail inspection.

Suggested order: fixes 1–8; then 13–17, 19 and 26–28; measure; apply justified asset/GPU/worker changes; finish with a visual polish pass. Avoid a new state-management library, a replacement UI kit, or a database rewrite for this work.
